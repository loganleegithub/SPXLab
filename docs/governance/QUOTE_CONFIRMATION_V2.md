## 原因

11:40窗口中7630上翼的价格没有新回调，而数量持续更新。旧RAW_FIELD_V1要求每个价格回调年龄≤2秒，导致有完整缓存但价格未变化的侧面持续被判过期。不能据此断言数据权限缺失或交易所没有流动性。

原始证据见 `var/2026-09-15/diagnostic-002/quality-review.json`。同时读取已安装ib_async 2.1.0的decoder与wrapper：decoder直接转发价格回调，wrapper的独立tickSize会使用该侧已有价格；不存在本项目在接收价格回调之前过滤重复价格的证据。IB目前[官方入门文档](https://www.interactivebrokers.com/docs/tws-api/doc/quick-start/requesting-market-data)说明价格/数量分别回调；[旧版官方接口说明](https://interactivebrokers.github.io/tws-api/interfaceIBApi_1_1EWrapper.html)明确独立数量更新。旧页面已标记弃用，本次以本机实际回调和所用库实现共同核验。

还修复一个潜在误用：数量归零或价格无效后，后来的数量事件不能重新启用已经撤回的旧价格；必须先得到新的有效价格和对应数量。

## 新契约 SIDE_CONFIRMATION_V2

原始FIELD价格、数量、时间、序号不改写。另维护每个合约每侧的价格依据、数量依据和确认依据。

1. 新价格到达后，必须等待同侧后续数量，不能借用前一价格的数量。
2. 同侧正数量回调可确认已经初始化、尚未撤回的该侧价格；不把它说成新的价格回调，也不说它是交易所精确时间戳。
3. 数量归零、无效价格、断线、市场数据类型变化或换订阅后使关联失效。单纯恢复正数量不能复活旧价格。
4. 请求ID和连接世代必须匹配；迟到旧请求不更新新订阅的报价投影。
5. 成交侧确认年龄≤1秒，对侧≤2秒，必要侧跨腿确认差≤1秒，尺寸仍为1/2/1，盘口仍不能倒挂。没有新确认时继续过期。
6. last、Greeks、另一侧数量不能替这一侧确认。原始价格时间保留在quote_refs，确认序号另存side_confirmation_refs。

这是对本机IB有序增量流的工程解释，不保证真实组合单能按合成价格成交。全包处理完成后才评价组合，继续保留断线及未知状态。
