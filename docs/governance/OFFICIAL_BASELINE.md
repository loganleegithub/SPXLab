# Codex / GPT-6 官方依据与本项目采用方式

核验日期：2026-09-15 · 状态：来源已读取，采用方式为本项目建议。没有修改 Codex 全局配置、模型选项或安装插件。

## 1. 名称和作用范围

本次读到的官方名称是 **GPT-6 Astra**，API 标识为 `gpt-6-astra`。用户用语“ChatGPT-6”暂按待澄清的名称保留，不把 ChatGPT 产品、Codex 开发环境和 API 模型视为同一接口。[官方模型指南](https://developers.openai.com/api/docs/guides/latest-model)

该指南说明了异步工具调用、工作中接收新指令、上下文压缩等能力，也要求应用负责工具执行和待完成工作。模型能力不是券商服务的时延、持久性或交易正确性保证。[同页能力说明](https://developers.openai.com/api/docs/guides/latest-model)

**本项目建议：** 使用这些能力完成资料核验、开发、审查和持续讨论；是否在运行时调用模型仍为 D01。异步查询可改善开发效率，市场决策仍依赖明确的事件时间、顺序和固定规则。本次没有因模型支持多代理就建立多代理架构。

## 3. 文档治理不是把提示词写得更长

以下结构是我们为本项目设计的方案，并非 OpenAI 官方要求固定使用这些文件名：

- 稳定协作约定进入 AGENTS；当前状态和人类选择进入决策记录。
- 系统边界与验收进入开发方案；原始事实进入带时间和范围的证据索引。
- 正式实验记录策略、数据、费用和成交模型版本；后续会话依据这些记录恢复工作。
- 重复出现且已验证的工作再考虑抽成 Skill；目前不新建工具集或调度系统。

官方最佳实践讨论了按需要采用 MCP、将重复工作形成 Skill、稳定后再自动化。本项目将只读 MCP、自动日报等保留为后续需要成立时的选项。[Codex 最佳实践](https://learn.chatgpt.com/guides/best-practices)

## 4. 如果以后选择运行时模型

Structured Outputs 能限制输出结构，官方同时明确结构化结果仍可能出错，还需处理拒绝或不完整输出。[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)

因此本项目建议把模型结果作为候选解释：保存原图、模型/提示词版本、调用输入输出与完成时间；经目标日期、中位数、概率带和来源校验后才形成可用预测。评估至少覆盖日期含糊、旧图替换、多产品混入、提取失败和晚到；无法校验则隔离。不能以模型自报置信度直接放行。

若实际采用 API，再按当时官方文档选接口与参数、评估成本和延迟、明确重试边界。本轮不是 API 迁移任务，不预设运行时模型预算、上下文长度或速度承诺，也不把订阅账户可用性当作已验证事实。

## 5. 复核与维护

来源页均实际打开或抓取正文；没有只用搜索摘要得出结论。旧 Codex 路径当前会跳转到 ChatGPT Learn，文中保存实际落点。Markdown 抓取用于读取正文，没有将官方全文复制到本项目。

涉及模型/API/工具选择时重新核验相关页面；普通本地文档修改不需要重复全套检索。记录本地采用建议与官方事实的区别，避免将本项目的规范包装成“官方唯一开发范式”。
