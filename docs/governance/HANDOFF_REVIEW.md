# 交接方案审查

版本：0.1 · 2026-09-15 · 状态：IN_REVIEW。审查对象为外部交接 v1.0，原文件未改动。审查人：本任务 Codex；本轮没有独立第二审查人。

## 结论

原方案适合作为战略与研究交接基线，尚不是冻结的施工规范。它已经正确区分行情接通、预测信息价值、可成交价格及净收益，也为缺失样本、版本回填、费用、订单失联和真实资金授权设置了具体边界。

需要补充的是：当前授权状态、研究参数的冻结责任、关键接口的精确语义，以及每项验收的证据层次。建议保留主路线和模块边界，围绕用户确认的一日完整影子闭环收拢第一轮范围。

## 2. 应保留的设计

1. 先用公开预测作为待验证输入，不急于复刻作者未公开模型。
2. Gateway 和常驻程序承担数据及未来执行；插件辅助核对。
3. 按当时收到且已完成校验的版本决策；晚到和含糊目标不能回填。
4. 同时记录 Balder、现价中心和现金对照；计划日不因亏损或缺失被删掉。
5. natural ask 为明确的合成报价假设，midpoint 为敏感性；都不冒充成交。
6. 影子、券商模拟、真实执行保持分开；未知订单先对账；预算考虑挂单和残腿。
7. P4 同时需要研究、执行、运营证据及具体资金授权；样本数不会自动启用实盘。

## 3. 开工规范需要处理的发现

### F01 · 旧启动说明与本轮授权冲突

原 [启动说明](/Users/logan/Codex/2026-09-15/yan/outputs/spx-project-handoff/NEW_PROJECT_BRIEF.md) 要求复制交接包、建立项目并实现系统。用户本轮明确要求先讨论再施工。把原说明直接放入代理上下文而不标注状态，会让旧命令与新任务混杂。

处理：原包为只读历史资料；本项目 `AGENTS.md` 和决策记录明确本轮仅文档治理。人类确认具体方案并允许实施后再更新范围。此项当前已落实为文档约定。

### F02 · “首轮 P0/P1”实际包含部分 P2

原 [交付计划](/Users/logan/Codex/2026-09-15/yan/outputs/spx-project-handoff/04_DELIVERY_PLAN.md) 将连续采集放在 P1，将固定规则、对照、费用、结算和回放放在 P2；启动说明又把这些都列入首轮。

用户已确认首轮需要一日完整影子闭环。处理：把首轮定义为跨 P0/P1/P2 的工程交付，正式实验依然单独冻结。没有合格事前预测或费用、结算缺项时，只能验收对应分支，不能把“状态页运行”当成完整 Balder 闭环。

### F03 · 事件公共字段与预测 Schema 的包装关系缺失

[数据契约第 1 节](/Users/logan/Codex/2026-09-15/yan/outputs/spx-project-handoff/05_DATA_CONTRACTS.md:9) 要求每个事件带 `event_id/mode/correlation_id` 等字段；随包预测 Schema 是封闭对象，没有这些字段。静态反例确认：直接给预测对象加 `event_id` 会被结构校验拒绝。

这不证明原 Schema 错误；它可能有意定义事件内容，但没有写清外层结构。建议定义 `EventEnvelope(payload=ForecastSnapshot)`，明确外层与内容各自版本、模式来源和唯一 ID 关系。补一个完整事件例子及直接混加字段的拒绝例子。

### F04 · VALID 与“V0 可使用”需要显式分层

随包 Schema 已声明仅管结构。静态构造一个目标和时间完整、`median=null` 的 VALID 记录仍可通过结构校验。对一般分布记录这未必非法，但 V0 无法据此选点。

建议分别表示结构通过、来源内容校验、目标/时间资格、V0 特定资格。V0 必须有明确中位数，且使用它的所有原始资产均在决策前到达；每张图、网页的接收时刻分别记录。旧隔离例子带网页捕获时间并引用后来核对的图片，目前因不可用状态并未污染研究，未来有效记录不能沿用这个简化。

### F05 · “首次合格”和计时器边界没有完全定义

原 [研究协议第 3 节](/Users/logan/Codex/2026-09-15/yan/outputs/spx-project-handoff/02_RESEARCH_PROTOCOL.md:35) 固定了 10:05、15 秒窗口、1 秒延迟，但还需明确：

- 现价中心使用截止前最近合格 SPX，还是窗口内首次合格 SPX？后者改变与预测的比较时点。
- 10:05 已有合格缓存、恰好 +1 秒没有新报价时，计时器是否检查当前状态？
- 相同接收时间、截止同刻、进程重启后，事件与计时器按什么顺序处理？
- 只存了 `received_monotonic_ns` 不足以定义跨进程重启顺序。

建议：截止时冻结预测及现价中心；缺合格现价时对照跳过，Balder 是否继续取决于冻结的通用质量要求。持久化全序号、运行/连接世代和计时器事件；明确同刻优先序，边界采用单一约定。延迟评估允许检查重建状态，但仍满足字段年龄和连接世代，不能伪造新回调。选择须在契约冻结前确定。

另需为截止前出现的新中心准备订阅：只在 10:05 才决定订阅最多六腿，可能无法在 15 秒内取得合格状态。设计一个有限预订阅范围，记录覆盖失败；不能为了等数据自动延长窗口。

### F06 · 断流未成交与观察不完整需要不同结果

原协议规定窗口内没有合格报价记未成交；契约又提供 `INDETERMINATE`。尚未规定意图发出后掉线、记录尾部丢失、程序整个交易日未运行时，何时能确定零交易、何时只能承认不知道。

建议：事前规则明确拒绝新增且无意图，记 NO_TRADE；在完整观察窗口内无资格报价，记 ASSUMED_NO_FILL；意图后的必要观察缺失，记 INDETERMINATE 并保留覆盖缺口。整日宕机通过事前计划日历生成缺失报告，不伪造当天实际执行的 Decision。所有计划日保留，未知日给数量及情景范围，禁止默认为盈利或零。

### F07 · 报价新鲜度需覆盖数量与敏感性

原协议的 2 秒年龄/1 秒侧间跨度主要面向两翼 ask 与中腿 bid；数量、另一侧价格、连接世代也会影响 bid≤ask 检查及 midpoint 结果。

建议把各字段的事件引用、有效条件与是否决定主场景写清。主场景资格与 midpoint 资格可不同，但应记录“主场景可算、中间价敏感性缺失”，不能用旧另一侧盘口制造精确中间价。2 秒规则本身是调试提案，先量化拒绝率，再在正式期前冻结。

### F08 · 影子价格上限与未来限价单不等价

原影子模型在延迟后采用“仍低于总成本上限的首个 natural ask”；未来券商模式描述为“一次固定限价提交、不追价”。例如初始 5.50 点，1 秒后 6.00 点仍低于费用后上限，影子可能认定成交；若券商限价固定为 5.50，结果不同。

这是模型差异，不能称影子计算有错。需要明确首轮检验的是“按最高容许价格取得后续报价的反事实”，还是“固定初始限价的反事实”。建议保留交接模型为调试基线，另登记未来限价映射与成交偏差；正式影子向 P3/P4 外推前必须解决，不得暗中借执行实现改变研究定义。

### F09 · 净收益门槛和资金分母需补齐

原配置的费用模型、固定成本分摊、最低经济效果及统计方法为空，原协议已承认不能据此形成合格净收益结论。

建议正式冻结时分别定义：绝对平均净损益门槛、相对现价对照的成对增量门槛；明确两者各扣了哪些固定成本，避免“已扣费用的净值”再机械重复覆盖同一费用。现金比较的利息/机会成本单列。

每组日损益除以 $1,000 可作为标准化研究尺度；它不是初始只有 $1,000 的账户净值曲线。若每天重新使用 1 组，连续亏损可能耗尽该初始本金，必须说明固定名义规模、是否补资及资金路径口径。当前不代填实盘金额。

### F10 · 正式实验的统计协议仍未冻结

100 日是评审节点提案；没有最低效果、区间方法、块长、缺失日处理、延长期限和版本变更规则时，不能称预注册完成。5–10 日调试可识别工程失败，对偏态收益和跨状态方差的估计可能仍很不稳定。

建议先完成方法和经济口径讨论，允许调试后提交具体参数。采用一个主要绝对指标和一个成对增量指标；块重采样方案及敏感性范围预先写明；不每日寻找显著性后提前宣布成功。模型源版本变化或正式期程序 bug 产生受影响清单，不能悄悄替换历史结果。

### F11 · “结算来源已引用”还不等于可用数据入口

原包正确要求匹配 SPXW PM 正式结算，但没有交付该记录的稳定获取方式、发布时点和修订样例。需要把结算定义、实际数据来源、最终费用/现金对账分开。

首轮可设计有证据的人工结算导入，保持自动来源适配接口；人工数值也必须有原始凭据和核对记录。取得正式来源前只能展示 pending/估算，不能拿最后一分钟 SPX 或普通 AM 的 SET 替换。

当前打开的 Cboe 规格支持乘数 100、SPXW 到期正常日 16:00 ET/半日 13:00 ET 停止交易；页面产品快照标注 2024-03-19，并未因此解决本项目实际结算数据接入。[Cboe 规格](https://www.cboe.com/tradable-products/sp-500/spx-options/spx-specifications)

### F12 · 后续执行与运维要保留可验证缺口

订单状态图是概念简图，未列出所有直接成交、取消与部分成交交错、更正、终态晚到事件。实现时应以订单、成交事实和持仓分别建模，不能把图中缺少的箭头当成不可能事件。

首轮只保留未来执行接口和模式隔离，订单提交能力在 P3 范围另行实施。P3 需要路由支持、原子预算、执行领导者、防重发、现金/持仓对账及恢复证据。模拟与真实环境行为可能不同，模拟成功不补齐真实成交能力证明。[IBKR 模拟限制](https://www.interactivebrokers.com/docs/tws-api/doc/notes-limitations/limitations/paper-trading)

## 4. 证据继承还需要注意的事项

- 原包包括 JSON 观察摘要和报告，并不全部是未经加工的供应商原始响应。Gateway 记录没有逐字段回调序列；QC 没有原始云日志全文。因此可参考能力结论，不能拿它们充当生产回放数据。
- `ledger-metrics.json` 的 `gross_payoff_w10/w20` 与旧报告明确使用最近 5 点网格得到的 2.313/6.447 不同；指标文件未明确相同取整定义。本轮复算支持旧报告的半点向上网格结果，保留早期指标原样并标为探索性，不自行解释差异成因。
- 探针是历史数据检查：日期硬编码、浮点计算，没有完整生产质量校验。阅读和语法通过不代表适合直接迁为策略或采集服务。
