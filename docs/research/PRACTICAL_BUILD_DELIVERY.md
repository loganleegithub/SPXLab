## 复跑与使用

以下在仓库根目录执行，output必须使用新目录。真实转录、逐腿行情及来源文件仅在忽略版本控制的var/保存。

```sh
.venv/bin/python scripts/prepare_reviewed_dataset.py \
  --inputs var/practical-build-2026-09-16/inputs/reviewed-inputs.json \
  --quote-bundle var/practical-build-2026-09-16/inputs/quote-bundle.json \
  --output var/practical-build-2026-09-16/report-next
```

输入清单逐行指定source_path/source_hash及settlement_path/settlement_hash。脚本验证中位数标识、产品/日期、成熟顺序及原件hash；拒绝项和缺失项单独留存。原有dataset-check可直接检查输出manifest。报价帧重建脚本见证据目录，读取原003日志前缀并核验链，不写原运行。

新增入口只在新研究计划满足既有条件时使用：

```sh
.venv/bin/python -m spxlab.cli value-shadow --plan /absolute/path/to/accepted-plan.json --directory /absolute/path/to/new-run
```

该命令使用client_id 27217，observe仍用27216；不应与当前观察同时启动。首次freeze绑定新源码，恢复时必须用该run的implementation/src加载CLI。原有round2_start仅启动已授权观察模式，未扩大成影子启动器。

模型生产者完成计算后，把新版本JSON原子落入新run的model-inbox/。必须含provenance.model_artifact_path和model_artifact_hash；正式模式的hash必须在冻结accepted_model_hashes中。内置build-distribution现同时输出model-artifact.json和distribution.json，真实输入的计算完成时刻由CLI实际打戳，仍保持EXPLORATORY/POINT_ONLY。改变标签不能使它成为合格DV1。重复文件或重启不会重复入库；被拒文件需检查原因后提交新内容。
